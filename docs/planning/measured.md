# what the completed milestones measured

these paragraphs were written inside [milestones](milestones.md), one per milestone, as that milestone
closed. they are moved here unchanged, for the reason [the reordering](reordering.md) gives: four fifths of
the milestone file had become retrospective evidence, and a sequence nobody can find is not a plan.

nothing here is edited. the append-only clauses stay append-only, including the two M-2 corrections that
the paragraph makes in place and the M-3 sentence kept "as the state M-2 measured rather than a claim about
the tree". a milestone's forward-looking half — what it still owes — stays in
[milestones](milestones.md), because that is a claim about work rather than about evidence.

## M-1: semantic prototype

define typed values, requests, rules, dependency recording, structured diagnostics, and an in-memory query interface.

status: complete.

evidence: the rust prototype has a typed pure step machine, exact-interface rule selection over the current interface subset, cycle diagnostics, dependency recording, instance-owned graph identities, exact in-memory reuse for completed pure applications, structured diagnostics, and an in-memory query surface. it constructs versioned, domain-separated pure-computation keys over separate stable rule identity and cache-invalidating rule revision (0023). action capability requirements propagate canonically through completed pure dependencies, and actual capability use is retained as dependency edges and exposed through the query interface.

persistent graph and cache storage, equality-based change pruning, and invalidation explanations belong to the incremental and caching work in M-2. operational support for `Observation`, `Mutation`, and `Opaque` belongs to the milestones that exercise those effects. neither is required to reopen this semantic prototype milestone.

## M-2: action prototype

add content-addressed blobs and trees, sandboxed local actions, caching, and explanations for cache hits and invalidation.

status: complete at its own scope. the paragraph below is append-only and two of its clauses were overtaken inside M-3 without being retracted; both are corrected in place now. what M-2 still owes is named at the end of it.

current evidence: blobs and trees are content addressed, with tree identity preserving file executability and symlink targets; the engine accesses them through an injectable pith-owned content-store interface. the in-memory and filesystem adapters implement that interface. the filesystem adapter atomically publishes blob bytes and canonical tree manifests, verifies identity on reads, and preserves content across store instances. pure steps can request deferred blob materialization, and action planning produces a validated, inspectable contract with a stable digest. pure computation keys use the stable rule identity and cache-invalidating revision from decision 0023. every scheduler run supplies an action policy, named allow and deny decisions are retained in provenance, and denial prevents executor invocation. the engine materializes only declared executable and input content for an executor, imports captured output bytes and trees into the engine store, and gives action rules engine-owned content identities. executors still return structured reports, and the engine retains successful and rejected reports in provenance. every computation that leaves `Pending` is published to a pith-owned engine-state interface, and a pure request that this engine instance has not evaluated is answered from the durable reusable index after its recorded dependency set revalidates: the completed attempt loads into a fresh arena node carrying the durable identity of the attempt it came from, so later computations depend on that attempt rather than a duplicate. equality-based change pruning exists for this path — a dependency recomputed to a canonically equal result leaves its consumers reusable — but not yet as a general propagation mechanism. a sqlite adapter stores that state as normalized relations, and a result computed by one process is hydrated by another after the writer has exited. the two adapters are held to each other by a generated conformance suite rather than by a shared encoding. reopening the database marks attempts left `Pending` by an interrupted owner as cancelled, so a reader finds a consistent graph rather than one waiting on a process that will not return, and finds it recorded as work that was stopped rather than work that failed. invalidation explanations are built as a chain over the recorded dependency graph: `EngineStateStore::explain_invalidation` walks the latest completed attempt's recorded reuse reason, following the single dependency it names, and both adapters share the walk through a common `AttemptLookup`-driven builder. the live arena exposes the same chain through `EngineQuery::explain_invalidation`, and the cross-adapter conformance suite compares the explanation for every pure key alongside the existing reuse and history reads. a first-party executor exists: `pith-executor-local` stages declared inputs and the executable into a per-action scratch root, runs the child with only the declared environment, captures declared outputs back from that root, and refuses a spec whose network policy or platform it cannot honor rather than running it under a weaker contract. its confinement when this milestone closed was partial — the child got `no_new_privs` and neither the landlock ruleset nor the seccomp allowlist decision 0028 describes — so it reported `AccessVerification::Unverified`, which is what it had installed. both layers landed inside M-3 and it now reports `Prevented`; the sentence stays as the state M-2 measured rather than a claim about the tree. independent work evaluates concurrently: a rule body declares that a batch of requests do not depend on one another with a single fan-out step, `run_many` drives one chain per root request, and the scheduler overlaps their actions while each chain stays on the synchronous step machine (0029). the overlap is measured rather than assumed — a test holds three actions at a barrier that only releases once all three have arrived. a run is cancellable: `run_cancellable` polls a caller-supplied signal at scheduling boundaries, and work stopped that way is recorded `Cancelled` — a terminal state distinct from `Failed` in the arena, in the durable record, and in the cross-adapter conformance suite — so a reader can tell a computation that cannot work from one that never got to run. the local executor kills its child when a cancelled action's future drops. that overlap is bounded: a chain that stops for an action queues the request and the driver starts it only while fewer than `Engine::action_concurrency` actions are running, so a fan-out of a thousand requests holds a thousand chains but plans, materializes, and spawns a bounded number of them. the landlock ruleset is installed (decision 0030 confines the scratch root, declared outputs, and declared toolchain closure), and the seccomp allowlist followed it inside M-3. what remains from this list is timeouts — there is no timeout, deadline, or resource limit anywhere in the workspace, which is also the backstop limit 0018 and 0022 both require and 0028's unresolved section claims the executor accepts — and cancelling part of a run rather than all of it. action caching is no longer disabled: decision 0031 splits action identity into a request-side key that indexes a completed attempt and an execution-side admission test that decides whether the recorded attempt may be served to this run, so an unchanged action is answered from the reusable index within one engine instance and across instances. a completed pure attempt holding an action dependency now enters the reusable index (decision 0033). its action edge is revalidated by re-selecting the recorded interface against this run's action rules, calling `plan()` on the recorded inputs, and comparing the key that derives to the one the attempt was recorded under; the current run's policy authorizes the contract that plan produced, and 0031's admission test decides whether the recorded execution may be served. a key that derives differently does not make the consumer dirty on its own — the engine reads the latest reusable attempt under the new key and compares its result to the recorded one, which is the equality-based pruning across the effect boundary 0031 left open, at the edge a build most wants it at. revalidation is run-scoped for this reason: `ReuseContext` carries the policy and executor identity from the driver to the reuse path, and `Engine::evaluate_pure` has neither, so it declines any attempt carrying an action edge, matching its refusal to take an effectful step. `ReuseReason::EffectfulDependency` is no longer produced by either the arena or the publication validator, and an action edge whose target is reusable stops blocking reuse.

## M-3: first build library

build a small project with at least two toolchains, generated input, tests, and fine-grained rebuilds. all build concepts use public library APIs.

status: complete at its own scope, against the four items its own statement names. U-5's remainder — multi-language targets, a check concept distinct from a test, remote execution — is not in it and has no milestone; M-7 holds the remote-execution half.

current evidence: one toolchain runs, declared as a closure of host paths and confined by landlock. `crates/pith-executor-local/tests/real_toolchain.rs` compiles a C source file to an object file through `Engine::run` and the local executor — the engine plans the contract, materializes the source, the executor execves the declared compiler path with a landlock ruleset over the scratch root and the declared toolchain closure, captures the object, and content-addresses it, with no change to the engine for a tool it did not author. the toolchain enters the contract as a declared closure of host paths (decision 0030), obtained from `nix path-info --recursive` over the compiler's store path. that discovery began in `crates/pith-executor-local/tests/support`, not in a library: 0030 gives it to the build library this milestone opens, and until xylem existed the tests stood in for it. `Toolchain::discover` is now that library API. the test support was not removed and still serves five test files, and the two implementations diverge — the support falls back to `LD_TRACE_LOADED_OBJECTS` for a driver outside `/nix/store`, which the library refuses outright as `DiscoveryError::Incomplete`, so the shipped API is narrower than the scaffolding it replaced. two runs of the same compile in different scratch roots produce byte-identical objects, so this compile is deterministic in the sense 0014 keeps separate from confinement.

running the compiler under the ruleset found two more things. **a toolchain needs somewhere to write.** the assembler creates temporaries, and confined to a scratch root it cannot reach `/tmp`. the executor now creates a `tmp` directory beside the working directory and exports `TMPDIR` naming it, so the temporary directory is part of the sandbox the executor builds rather than something every action has to remember to declare. **`ldd` does not answer the closure question.** it picks a loader from `PATH`, so inside a nix devshell it resolves a distribution binary against nix's glibc and names libraries that binary will never open; asking the loader named in the binary's own `PT_INTERP`, via `LD_TRACE_LOADED_OBJECTS`, is the answer that matches what the kernel opens. the nix store path avoids the question entirely, which is why 0030 makes it the supported one.

the slice that first ran the compiler found three things, each of which changed what the build library has to be. **a toolchain is not an executable** — resolved by 0030: `ActionSpec::executable` is now a host path and a declared `toolchain` closure carries the paths the action may read, so landlock confines the toolchain the action actually used rather than a convention. **the seccomp allowlist in 0028 named a third of what a compiler needs**, and the missing part is structural rather than incidental — process creation, because the driver is a supervisor. that layer is now installed: the filter admits 77 syscalls, each measured from a compiler, the linker, or the shell fixtures and commented with what asked for it, so `AccessVerification` reports `Prevented` — both path and syscall confinement kernel-enforced — and a child issuing a syscall outside the list dies on `SIGSYS`. both layers' measurements are recorded in 0028's unresolved section, and 0028 is now `accepted` on the criterion it set for itself. **fine-grained rebuild needed an action identity**, which is decision 0031: the second run of an unchanged compile plans the same contract, derives the same `ActionComputationKey`, and is served the first attempt.

action results are cached (0031). the key is the request half of action identity: the selected rule's identity and revision, the requested interface, the request inputs, and the digest of the contract planned from them. the execution half is knowable only after an executor has run, so it becomes an admission test when reuse is considered — the recorded execution must come from the executor and platform this run would use, its `AccessVerification` must meet the engine's floor, its recorded dependencies must revalidate, and the content it produced must still be in the store. any of those failing is a miss, and the action runs. `Executor` gained `identity`, so the engine can ask who is about to run before it reads the index, and both engine-state adapters carry a reusable action index that the cross-adapter conformance suite compares alongside the pure one. the consumer of an action stayed out of the index at first and recorded `EffectfulDependency`, on the reasoning that a pure key does not carry the identity of the action rule that will be selected, so a pure result recorded before that rule was revised could otherwise be served after it. 0033 answered that by re-selecting and re-planning the recorded request at revalidation, and the reason is now unconstructible — nothing in the workspace produces `ReuseReason::EffectfulDependency`, and an action edge whose target is reusable no longer blocks reuse. what reuse skips is the execution, which is where the cost sits. `ActionCachingDisabled` now means `Engine::set_action_caching(false)`, and the determinism check runs under it, because a served result is identical for having the same bytes and says nothing about what the tool would produce a second time.

the first build library exists: `crates/xylem`, the first crate to take a botanical name (docs/foundation/name.md). it owns the toolchain closure discovery 0030 assigns to it — `Toolchain::discover` is the public API the test support in `pith-executor-local` stood in for — and declares compile and link actions over the nominal types 0026 names, which Phase 0 of the calculus made inhabitable. a toolchain is a `Value::Nominal` request input so dispatch distinguishes compiles over different toolchains, and `CSource`, `Object`, and `Executable` are distinct nominal content types so two content-producing rules no longer collapse to `() -> Blob` and collide as `E-1102`. the two-source build fixture in `crates/xylem/tests/two_source_build.rs` is the first time the repository asserts U-5's fine-grained invalidation: touching `a.c` recompiles `a.o` and re-links, but the `b.o` compile is served from the reusable action index, so the second build adds three action computations rather than five — `a`'s discovery, `a`'s compile, and the link, against a cold build's five. the counts include the per-source depfile discovery action 0034 added later in this milestone, which is why they are not the two-against-three a pre-0034 reading gives. the fixture now builds over a sqlite state database beside its filesystem content store, which lets it assert what decision 0033 added: a second build of unchanged sources reports `Reused` at the root and plans no action, and a fresh engine opened over the same root after the first is dropped reports `Hydrated` and allocates no computation beneath the root. before 0033 every target of a build sat above an action and so re-ran on every build, surviving no process boundary. header dependencies are discovered rather than declared by hand (0034). a `-MM` depfile pass runs as its own sandboxed action over a declared header universe, a pure rule parses the captured depfile, and the discovered paths reach the compile as a request input the planner resolves to content identities. that keeps `plan()` a function of its inputs and the rule's own state, which is what 0033's revalidation walk rests on: a planner reading the depfile off the filesystem would answer differently on two identical runs. `an_undeclared_header_fails_rather_than_reading_the_host` is the evidence the universe is load-bearing, since the landlock ruleset makes an undeclared header unreachable rather than stale, and editing a shared header recompiles both objects.

linking is over a list (0035). `link_interface()` is `(Toolchain, List<Object>) -> Executable` over the `List` constructor the 0026 slice landed, each object staged at a path derived from its position so the planned contract is a function of the list, and the element type keeps nominal identity so rule selection stays unambiguous (0015). a three-source build links all three.

a build runs under any registered toolchain, and two of them share one graph. `Toolchains` holds the discovered set and each rule resolves the closure for the driver a request names, so one registration serves both: registering per toolchain would give two rules one interface and collide as `E-1102` (0015). the fixture compiles the same source under a nix gcc 15.2.0 and a nix clang 21.1.8 and asserts that clang's compile plans its own actions, that the two produce different objects, and that gcc's entry still answers afterwards. that is what makes "a toolchain is a request input" a measurement rather than a comment on the type.

the second toolchain paid for itself twice before it built anything. `Toolchain::discover` required the driver to name a separate compiler through `-print-prog-name=cc1`, which gcc does and clang does not, so discovery returned `Incomplete` for a compiler that was sitting in the devshell; `program_path` is now optional and `COMPILER_PATH` is declared only when there is one to declare. and clang needs three syscalls gcc never issued — `sigaltstack` for its crash handler's stack, `rename` because it writes output to a temporary and moves it into place, and `alarm` for a watchdog around its own work — which is 0028's prediction that the allowlist widens per toolchain, measured a second time.

both of those were found by a test that had been passing while doing nothing. `Toolchain::discover("clang")` failed, the fixture's `else { return }` skipped, and the run was green. the two-toolchain test now distinguishes the two cases it was blurring: a host without clang skips on `DiscoveryError::NotFound`, and a clang that is present but undiscoverable fails. the rest of the fixture still carries the older shape, where a skip and a pass are the same green.

tests are a build concept (0036, 0037). the test action's program is the executable the graph produced, staged from the store and confined by the same two layers as a compile, and its contract reports the exit status instead of failing on it, so a failing test is a verdict rather than a broken action. the fixture asserts a passing verdict, a failing verdict from a run that did not fail, and that an unchanged failing test is served from the reusable index rather than re-executed — the case a failed action could never give, since a failed computation is not in the index.

generated input reaches a compile through the graph. a generator is built, run as an action whose program is that produced executable, and the source it writes is captured as a `CSource` a later compile consumes; touching the generator's source changes the generator, which changes the generated source, its object, and the link. the generate and test rules share their input types and differ in their output, which is the collision nominal identity exists to prevent (0026) and the first time two xylem rules have needed 0015's selection to tell them apart on output alone.

what M-3 still owes its own statement: nothing named in it. "at least two toolchains, generated input, tests, and fine-grained rebuilds" are each asserted against a real toolchain, and every build concept goes through xylem's public API. what remains is scale rather than capability — the fixture is a handful of files, not a small project. the skip-shaped-like-a-pass trap above is closed: every discovery site in the fixture now skips only on `DiscoveryError::NotFound` and fails on a driver that is present but undiscoverable. an empty run fails outright — `a_c_toolchain_is_available` panics when no C compiler exists at all, so a compiler-less host cannot produce a green run. the skips still print, but honestly: nextest captures the output of passing tests, so a skip message is visible only under `cargo nextest run --no-capture`; the failing sentinel is what makes the run's color mean something. M-3 also discharged the surface-syntax deferral 0026 and 0028 had pinned to it — by completing without a surface language, xylem being a rust library API — so surface work is now gated on the 0026 calculus landing in the core rather than on a milestone.

## M-4: package and environment libraries

add package identity, basic constraints, lock data, binary reuse, and a reproducible development environment.

status: complete.

evidence: `crates/phloem` prototypes each item as a record plus a measured claim. a package is a declared name in a domain with versions as coordinates over the domain's declared ordering, and a realization is identified by the computation and content machinery the kernel already has (0039). constraints, ranges, and preferences are values over that ordering; resolution is a host-rule computation in the graph under 0040's protocol — an answer carrying its choice and explanation, underdetermination refusing rather than letting a search order pick. the protocol names four values (constraint set, universe, preference order, budget) and the registered interface declares five, the declared version scheme being the fifth, so five inputs reach the computation key. the written lock is a text projection of a lock document carrying the resolver revision, the scheme, the preference list, and the universe digest beside the entries; render is deterministic, parse inverts it, and both the write and the read are caller effects the engine never performs (0041). binary reuse is an admitted substitution over a lock binding — four legs checked in a fixed order with the failing one named, the policy leg shipping as local admission of named origins — and a served substitution publishes no engine attempt where a refused one's build publishes exactly that attempt (0042). the development environment is a value over the lock: one resolution plus the realization coordinates it declares and the substitution records it served, rendered deterministically, with the lock's placement derived from the declaration — one lock per environment, `pith.lock` for the default — and resolving touching no path until a caller writes (0043). the milestone's records are 0039 through 0043, and none of them proposes a kernel constructor — but the milestone drove two into the core, which is the more useful claim and the one this file should track. `Record` and `Sum` both landed on 2026-08-14, the day 0039 was committed, and 0026's own landed-ahead section attributes both to it by name: 0039 needed a package description and a lock entry, and a source binding over a fixed set of constructors carrying different payloads. so the honest statement is not that the kernel does not change but that it converges, one domain at a time — `Nominal` came from 0015's selection collision, `List` from 0034's discovered header set, `Record` and `Sum` from 0039. what a milestone owes this file is which constructors and which encoding versions a domain drove; M-5a is the first that can confirm or refute convergence, because it is the first domain whose shapes the calculus was not extended for.

what M-4 still owes its own statement: nothing, after the three rounds that followed its close. 0044 took the fabricated-bytes objection whole — a registry adapter reads a real index, a fetch measures real archive bytes, the archive provenance names its registry through the origin the candidate carries, the git provenance materializes a tree and locks its measured content, and the witness question three records deferred is answered by a transparency log checked locally. 0045 took the last item: a locked source becomes a built artifact end to end, the fetched archive unpacked into a measured tree and the package's declared build running as one pure rule over xylem's compile and link entries, producing an executable that runs — so "a realization is identified by the machinery the kernel already has" (0039) is a measurement: the second build reuses and a fresh engine hydrates on the engine's machinery alone. 0046 took the deliberate deferral both records pointed at: the index line carries requirements, so one resolve request walks the edge over a real registry answer, and a dependency's artifact is a library — objects plus offered headers, built in-graph by a second package-build interface, its headers reaching the dependent's compiles as declared request data through the third input xylem's compile entry gained (the first xylem interface change in six records, argued against engine-registration composition). the edge reuses selectively: republishing only the dependency moves the dependent's artifact while the dependent's own compile is served from the reusable index, and republishing a package nothing uses moves the universe digest and no artifact — measured on linux, in the same VM devshell 0045's gated runs used. 0053 closed the diagnostic half those texts left in prose: every lock and index parse refusal now carries the file it was refused in and a span selecting the field, so the written forms a person edits render `path:line:column` with the offending bytes quoted, and the durable record keeps the span while dropping the source as context. 0054 then corrected the prefix those lines spell: it names the kernel's hash function, blake3, owned by `pith-ids` and bound into every written line by test; a line spelling another algorithm is refused, the message saying what it expected.

## M-5a: Linux system composition

compose files, users, a service, and boot configuration into an immutable Linux artifact.

status: complete.

nothing in that sentence needs an effect category the kernel does not have. a composed artifact is content: files and directories are trees, a user table and a unit description are records and declared sums, a boot configuration is a rendered text projection of them, and the tools that turn a tree into an image are ordinary actions under 0032's granularity. so this half runs on the kernel as it stands, and that is the point of splitting it out — it is the first domain whose shapes the calculus was not extended for, which makes it the first real test of 0021's design criterion, "a new domain implementable without a core patch."

the round is written with that standing explicit: a kernel change this milestone turns out to need is the round's most interesting finding and gets argued in a record, not assumed into the diff. M-4 drove two constructors into the core while its own statement claimed none, so an unexamined "no kernel change was needed" is the outcome this framing exists to prevent. the convergence tracking this file asks for has one entry no domain drove: 0055 changed `Int` from a machine integer to an arbitrary-precision one, on 0018's ground rather than on a milestone's, so a scalar's representation is the second thing after an encoding version that a round can move without a domain asking for it.

0056 landed the other half of that criterion ahead of the milestone, and the two halves are different questions. it adds `crates/example-domain`, a fixture domain registering one pure rule and one action rule through the public engine, depending on no other domain and named nowhere else in the workspace, which is the test U-10 asks for in its own text and the workspace never had; the peer claim had been an argument from two first-party crates, one of which depends on the other. what it settles is the registration surface: a domain the kernel does not know about gets reuse, cross-process hydration, and contract inspection from two calls. what it cannot settle is convergence, because its shapes are the ones the calculus already has, and that is the question this milestone exists to answer.

two things already in the tree become load-bearing here rather than latent. output-tree capture dereferences symlinks and can never emit a `Symlink` entry, which is currently unreachable because `symlink` and `symlinkat` are outside the seccomp allowlist — an immutable `/etc` is mostly symlinks, so this milestone is where that stops being a theoretical asymmetry. and the composition requirements C-2, C-3, C-4 and C-7 rest on a merge operator 0026 defers to a configuration library that no milestone creates; composing files and units is where a domain first needs one, and taking it in the library with a stated escalation path to the kernel is what 0009 and one-mechanism-per-concern require. 0052 took that deferral ahead of the milestone, grounded in the system-composition research note: the operator lands in the system library this milestone opens, disagreement fails closed with both owners named, deliberate replacement is the only way a value wins, and the escalation trigger — a second domain needing record composition — is named rather than implied.

evidence: `crates/stele`, the system library, registers three merges (etc, users, unit), three renders (unit file, passwd, boot entry), one assembly action, and the entry that requests them, through the same two registration calls every domain uses. 0058 is its record, and the round's finding is the one this section said it would be watching for: the calculus converged. stele declares twelve types over constructors that all predate it and drives no constructor, no engine or core change, and no encoding version — the first milestone whose convergence entry is an empty diff, stated as a diff over the seven kernel crates rather than an assertion. what the milestone demanded is in the first-party executor, both halves predicted above and each measured with a failing witness: capture now reads symlink targets instead of following them, so links and dangling links survive as declared content, and the allowlist admits three syscalls — `symlinkat`, `copy_file_range`, and `chdir` — named by the coreutils operations that issued them, 80 against 77 when the milestone opened. a third executor fact was measured rather than changed: 0030's finding that a toolchain is a closure, not a binary, reappears on the system tools, and the Tools value carries the loader's closure or the confined child cannot start.

0052's operator ships in this library with the signature and policy set its unresolved section deferred here: `agree` and `concat` per declared field, fail-closed for unlisted fields, the keyed overlay for files and users, and replacement naming the owner it expects to replace. the three tests 0052's measured section named as owed exist in `crates/stele/tests/merge.rs` and fail honestly — the conflict refusal names the field, both values, and both owners; the stale replacement names who declares the field now; the permutation test merges to one canonical result. the composed artifact is one canonical tree, and the confined linux suite drives it end to end: a real assembly under landlock and seccomp produces `Symlink` entries that survive capture, materializes with `read_link` reading what the store asserted by identity, reuses on the second compose, hydrates in a fresh engine, and two cold engines over two roots compose to the same identity. the granularity claim is a count: editing one unit fragment recomputes exactly three pure computations and one action, and the other merges are served. the host-agnostic composition suite runs the same contract script through a portable fixture executor that claims no confinement, so the artifact's claims are checkable where the first-party executor does not build, and the linux suite measures the confined half.

## M-8: the backstop limit

a time and resource bound on evaluation and on an action, as one mechanism.

status: complete.

evidence: [0059](../decisions/0059-a-caller-declared-run-bound.md) is the record, and the mechanism is
`RunBound` — a wall-clock deadline and a step budget declared by the caller per run, never defaulted,
taken by `Engine::run_bounded` and `Engine::run_many_bounded` while every earlier entry point stays
unbounded. the deadline is polled at the scheduling boundaries cancellation already polls; the step
budget is spent one step at a time inside the step machine, because a body yielding an unbounded
sequence of distinct requests — the shape 0050's predicate cannot refuse, since no request repeats —
crosses no boundary at all; and the deadline descends into every `ActionInvocation`, so the executor
holding a child enforces the clock while the driver sleeps waiting for it, which keeps a timer out of
the engine on the same discipline that keeps the runtime out of signatures. the bound's code is
`E-1216` beside `E-1215`, with one terminal rule: work the run was merely holding is recorded
cancelled, exactly as caller cancellation records it, while the action that exceeded its wall clock is
recorded failed carrying the bound's code, because it ran and produced nothing within the authority it
was given — and the refusal happens inside the executor before capture, which answers 0037's open
question by construction: no `Reported` rule ever reads a timeout kill as a signal-death verdict. the
deadline is authority, not content, so it participates in no computation key on 0031's own split.

the witnesses are six tests. `a_body_that_yields_forever_is_stopped_by_the_step_budget` stops a body
yielding fresh requests forever under a budget of fifty, with `E-1216` naming the stepping request's
label and the budget, every attempt terminal, nothing failed, the held work cancelled.
`an_expired_deadline_stops_the_run_before_any_work` is the boundary check, and
`a_generous_bound_leaves_an_ordinary_run_untouched` the control.
`a_timed_out_action_fails_itself_and_cancels_what_was_waiting_on_it` is the split: exactly one failed
attempt — the action's, carrying `E-1216` — and one cancelled attempt, the chain parked waiting on it.
in the executor, `a_child_that_exceeds_its_deadline_is_refused_with_the_bound_code` runs `sleep 30`
under a deadline one hundred fifty milliseconds out and finishes in a quarter second — the child died
at the deadline — and `a_generous_deadline_leaves_a_quick_action_untouched` is the control. the
workspace suite is 778 tests, 0 failures, with clippy and the xtask checks clean.

what the round also owes the notebook it paid: 0028's unresolved-section sentence claiming "the
executor accepts an optional timeout in its configuration" is retracted in place and named as the
older kind of debt, a record describing a facility nobody built; 0018's configuration question and

## M-9: observation identity and freshness

status: complete.

evidence: [0060](../decisions/0060-observation-identity-and-freshness.md) splits observation identity the
way 0031 split action identity without giving the two effects the same semantics. the request half is an
`ObservationComputationKey` over selected rule identity and revision, typed interface and inputs, and the
subject the observation rule deterministically derives. the world half is `ObserverIdentity` plus the
revision value returned by `observe`. a recorded edge is admitted only when the current rule re-selects,
the inputs re-derive the same subject and key, the current observer has the recorded identity, and its
`attest` returns the recorded revision. the observation attempt itself never enters the durable reusable
result index; the pure consumer above it does, and 0051's transitive walk reaches the observation before
that consumer is reused or hydrated.

`NeedObservation` is now in `PureStep` before M-11 fixes the represented-ir constructor set. the existing
`Resumption::One` carries the observed value back, so no parallel resumption form was invented. the
synchronous `evaluate_pure` path stays synchronous and rejects the step with `E-1206`; `Engine::run` has
an async reuse path that can attest observation edges in live and durable pure results. no configured
observer is `E-1217`. `Observer::attest` and `observe` both receive the caller's `RunBound`, extending
M-8's authority seam to the new external operation.

the thin prototype is a real file mtime. its five engine tests measure the relevant branches: first
observation followed by live root reuse after one attestation; cross-engine root hydration from shared
durable state after attestation and without observing again; changed mtime causing recomputation and a
second observation; observer-identity mismatch causing recomputation without asking the mismatched
observer to attest another observer's record; and the `E-1206`/`E-1217` boundaries. the key tests assert
subject sensitivity and digest-domain separation.

the durable record carries the request inputs, derived subject, intended observer, observed result and
revision. interrupted pending observations retain the observer they intended to use. both state adapters
validate that the stored key is derivable and provenance names that observer; SQLite round-trips the
widest observation record. the generated conformance grammar now creates observations, completes and
stops them, and places observation edges in later attempts, so the reference adapter and SQLite are held
to the same category, provenance and dependency rules rather than only fixture examples.
